# M1.2 Product Read Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a real, read-only product catalog path with deterministic seed data, SKU-aware queries, and Redis Cache Aside behavior while preserving service ownership boundaries.

**Architecture:** `product-service` owns `catalog_db` and exposes typed catalog query contracts. A small application service validates filters and maps persistence rows to response DTOs; the Gateway will call this contract through a typed adapter and expose read-only HTTP endpoints. MySQL remains the source of truth for product, SKU, stock, and promotion data; Redis caches only serialized product detail responses with bounded TTL.

**Tech Stack:** Go 1.25, Go-zero REST, `database/sql`, MySQL 8, Redis 7, `go-sql-driver/mysql`, `go-redis/v9`, table-driven tests, Docker Compose.

- [ ] **Step 1: Define the typed read-only contract**

The proto must expose `ListProducts` and `GetProduct`, with request fields for keyword, category ID, page, page size, product ID, and optional SKU ID. Responses must contain product/SKU IDs, title, specs, sale price, stock quantity/status, image refs, and active promotion summary. No model/user-provided price fields are accepted in requests.

- [ ] **Step 2: Write failing handler tests**

Test `GET /api/v1/products` for valid filters, invalid numeric filters, empty result, and dependency failure; test `GET /api/v1/products/{id}` for found and not-found. Assert stable JSON error codes and that internal SQL/gRPC text is not returned.

- [ ] **Step 3: Generate/implement the gRPC adapter and Gateway routes**

Use generated protobuf types if the local toolchain is available; otherwise keep the proto as the source contract and implement the smallest typed adapter required by the generated client. The Gateway must call the product client with request timeout, map `INVALID_ARGUMENT`/`NOT_FOUND`/`DEPENDENCY_TIMEOUT`/`INTERNAL`, and preserve `X-Trace-ID`.

- [ ] **Step 4: Wire the service process and seed startup documentation**

`product-service` must open its own catalog DSN, construct repository/service/cache dependencies, and serve the typed RPC on its configured listen address. Add a documented seed command that is idempotent and never logs the DSN. Gateway routes must remain read-only.
