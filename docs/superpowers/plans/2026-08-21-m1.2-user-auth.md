# M1.2 User Authentication and Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver registration, JWT authentication, self-profile management, and address ownership enforcement through the Gateway and `user-service` without cross-service database access.

**Architecture:** `user-service` owns `user_db` and signs/verifies HS256 JWTs through a shared authentication package. The Gateway validates protected requests, stores the verified principal and bearer in context, and forwards the bearer to user-service gRPC; user-service verifies it again and derives the current user ID from claims. Protected RPCs never accept client-controlled `user_id`.

**Tech Stack:** Go 1.25, Go-zero REST/zRPC, MySQL 8, protobuf/gRPC, `github.com/golang-jwt/jwt/v4`, `golang.org/x/crypto/bcrypt`, `go-sqlmock`, Docker Compose.
