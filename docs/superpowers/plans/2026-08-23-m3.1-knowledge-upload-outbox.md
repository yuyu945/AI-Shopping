# M3.1 Knowledge Upload Outbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first knowledge-service slice: authenticated document upload stores the original object, commits metadata and `knowledge.document.ingest` Outbox together, and publishes the event asynchronously.

**Architecture:** Keep MinIO, MySQL, and Kafka behind small interfaces. The upload service stores bytes first, then commits document metadata and Outbox in one `knowledge_db` transaction; if the transaction fails, it makes a best-effort object cleanup. The Outbox worker follows the existing M2 lease/retry publisher shape.

**Tech Stack:** Go 1.25, Go-zero zRPC style gRPC, MySQL 8.4, MinIO SDK, `kafka-go`, `go-sqlmock`, table-driven unit tests.
