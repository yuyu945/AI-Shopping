# M3.2 Knowledge Processing and Retrieval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build async document parsing, chunk embedding, current-version visibility, and product knowledge retrieval for M3.2.

**Architecture:** Keep parsing, embedding, vector storage, persistence, and transport separated by small interfaces. Consumers are ordinary services that can be driven by Kafka runtime later and by unit tests now; MySQL remains the source of truth for document/chunk state and current-ready visibility.

**Tech Stack:** Go 1.25, MySQL 8.4, Kafka Outbox pattern, MinIO, Alibaba DashScope embedding adapter behind an interface, Milvus REST behind a `VectorStore` interface, table-driven unit tests with fakes and `go-sqlmock`.

**Status:** Code scope completed on 2026-08-23 with DashScope `text-embedding-v4` / `1024`, Kafka reader runtime wiring, and Milvus REST adapter. Real external dependency integration tests remain explicitly gated follow-up work.

- [ ] **Step 3: Implement retrieval service**

Retrieval flow:

1. Validate `product_id`, `query`, `doc_types`, and `top_k`.
2. Load current-ready document versions for the product and requested doc types.
3. If none exist, return `FallbackReasonNoReadyKnowledge`.
4. Embed the query.
5. Search vector store with product/doc/version filters.
6. Rehydrate snippets from MySQL by chunk IDs and current-ready document filter.
7. Return snippets sorted by vector score.
