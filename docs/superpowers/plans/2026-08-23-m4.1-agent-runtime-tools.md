# M4.1 Agent Runtime and Controlled Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `agent-service` run/step persistence model and controlled read-only Tool runtime for M4.1.

**Architecture:** Keep model orchestration, Tool registry, persistence, and transport separated. Domain code depends on small `ChatModel`, `Tool`, and store interfaces; concrete gRPC clients and future Eino provider adapters are runtime wiring details.

**Tech Stack:** Go 1.25, Go-zero zRPC, MySQL 8.4, typed gRPC clients, JSON Schema strings for Tool declarations, table-driven tests with fakes and `go-sqlmock`.

---

## Self-Review Checklist

- M4.1 creates observable Agent Run/Step records but does not write final `recommendations`.
- Every Tool has a declared schema, timeout, max result count, and permission source.
- `get_user_profile` and `get_discount` do not trust model-supplied user IDs.
- The run loop always terminally marks every started Step.
- Model/provider raw errors are mapped to stable classifications.
- No business service imports model SDKs.
- No Agent code writes inventory, wallet, order, promotion, or arbitrary SQL outside `agent_db`.
