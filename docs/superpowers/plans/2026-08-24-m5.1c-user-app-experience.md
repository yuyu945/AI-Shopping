# M5.1c User App Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first browser user app for 智选购 that drives product browsing, AI guide recommendations, cart, order creation, wallet payment recovery, order detail, and review submission through existing Gateway endpoints.

**Architecture:** Create a Vite React TypeScript SPA in `apps/web`. Keep backend facts in Gateway responses; the frontend only renders snapshots and replays persisted order/run state after timeout or network uncertainty. Match the `docs/assets/video-reference-contact-sheet.jpg` user prototype: top navigation, red shopping status banner, tab-like category/search controls, product cards, and dense operational panels rather than a marketing landing page.

**Tech Stack:** Vite, React, TypeScript, Vitest, React Testing Library, plain CSS with CSS variables.

---

## Prototype Constraints

Use `docs/interaction.md` and `docs/assets/video-reference-contact-sheet.jpg` as layout constraints:

- User app first viewport: shopping UI with a top nav, a red status/guide banner, category/search controls, and product cards.
- AI guide: two-column desktop layout with conversation/run progress on the left and verified recommendation cards on the right; single-column mobile layout.
- Product detail: SKU controls and business facts at the top, then tabs/panels for detail and knowledge Q&A.
- Cart/order/payment: compact operational panels with clear status badges and stable button states.
- Do not implement the operations console screens from the contact sheet in M5.1c.
