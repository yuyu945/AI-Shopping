# M5.2c Operations and Behavior Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete M5 by adding minimal operations diagnostics for knowledge documents, Agent runs, and analytics events, plus reliable `behavior.events` Outbox/Kafka consumption.

**Architecture:** Extend existing service boundaries only: knowledge ops stay in `knowledge-service`, Agent ops and redaction stay in `agent-service`, behavior Outbox publication stays in Gateway, and analytics read models stay in `order-service`. Gateway exposes all operations routes under `/api/v1/ops/*` with an explicit MVP operator header gate.

**Tech Stack:** Go, gRPC/protobuf, go-zero Gateway, MySQL, Kafka adapter tests with fakes, React/Vite/TypeScript/Vitest.
