# M5.1 Agent Gateway HTTP and SSE Design

## Goal

M5.1 exposes the existing `agent-service` run and replay capabilities through the Go-zero API Gateway so the user-facing AI shopping guide page can create an Agent run, fetch its replayable timeline, and subscribe to a stable SSE feed.

## Current Behavior

M4.2 completed trustworthy Agent recommendations:

- `agent-service` owns `AgentRun`, `AgentStep`, and verified recommendation snapshots.
- `api/agent/agent.proto` exposes synchronous gRPC methods:
  - `StartRun(StartRunRequest) returns StartRunResponse`
  - `GetRun(GetRunRequest) returns GetRunResponse`
- `GetRun` returns the run summary, ordered steps, and verified recommendations.
- Runtime still uses the disabled model adapter. A real Eino/LLM provider remains outside this slice.

The Gateway already exposes product, user, order, and knowledge HTTP routes. Each service has a small internal gRPC client that forwards bearer auth, propagates a valid `trace_id`, applies a short deadline, and lets handlers map gRPC errors into stable HTTP JSON errors.

## Scope

M5.1 includes:

- Add `AgentRPC` wiring to `apps/gateway/main.go` and `apps/gateway/etc/gateway.yaml`.
- Add a Gateway `agentclient` package for `StartRun` and `GetRun`.
- Add authenticated HTTP endpoints:
  - `POST /api/v1/agent/runs`
  - `GET /api/v1/agent/runs/{run_id}`
  - `GET /api/v1/agent/runs/{run_id}/events`
- Return stable JSON DTOs for run summaries, steps, and recommendation snapshots.
- Expose SSE events derived from persisted `GetRun` state.
- Add Gateway unit tests for request mapping, auth/trace propagation, DTO mapping, stable error mapping, and SSE framing.

M5.1 excludes:

- Frontend page implementation.
- Real Eino/LLM provider integration.
- New agent-service streaming RPCs.
- Async Agent run execution.
- Cart/order writes from Agent recommendations.
- Operations dashboard and behavior/review event analytics.

## API Contract

### Create Run

`POST /api/v1/agent/runs`

Request:

```json
{
  "session_no": "sess_existing_optional",
  "message": "预算 5000，买一台适合编程和轻度游戏的笔记本"
}
```

Rules:

- The route is authenticated.
- `message` is required after trimming.
- `session_no` is optional. If empty, `agent-service` creates one.
- The Gateway does not accept `user_id`; identity is injected by JWT through the gRPC metadata bearer.

Response:

```json
{
  "run": {
    "run_id": "run_001",
    "session_no": "sess_001",
    "status": "FAILED",
    "final_text": "",
    "error_code": "MODEL_FAILED",
    "step_count": 1,
    "stream_url": "/api/v1/agent/runs/run_001/events"
  }
}
```

Because `StartRun` is currently synchronous, this response may already be terminal. The Gateway must not claim that a real live Agent stream exists.

### Get Run

`GET /api/v1/agent/runs/{run_id}`

Response:

```json
{
  "run": {
    "run_id": "run_001",
    "session_no": "sess_001",
    "status": "SUCCEEDED",
    "final_text": "已根据预算和用途推荐 3 款商品。",
    "error_code": "",
    "step_count": 4,
    "stream_url": "/api/v1/agent/runs/run_001/events"
  },
  "steps": [
    {
      "step_no": 1,
      "step_type": "TOOL",
      "tool_name": "search_products",
      "status": "SUCCEEDED",
      "error_code": "",
      "latency_ms": 45
    }
  ],
  "recommendations": [
    {
      "rank_no": 1,
      "sku_id": 2001,
      "product_id": 1001,
      "product_title": "ThinkPad E14",
      "sku_code": "TP-E14-16G",
      "sku_spec_json": {"memory": "16GB"},
      "price": "4999.00",
      "saleable": true,
      "discount_json": [],
      "reason": "预算内，内存适合编程。",
      "validation_status": "VERIFIED"
    }
  ]
}
```

`sku_spec_json` and `discount_json` are forwarded as JSON when the agent-service bytes contain valid JSON. Empty `sku_spec_json` is rendered as `{}` and empty `discount_json` as `[]` to keep HTTP responses valid JSON.

### Run Events

`GET /api/v1/agent/runs/{run_id}/events`

Headers:

```text
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

Events are replay/polling snapshots derived from `GetRun`:

```text
event: run_snapshot
data: {"run":{"run_id":"run_001","status":"SUCCEEDED","stream_url":"/api/v1/agent/runs/run_001/events"}}

event: step_snapshot
data: {"step":{"step_no":1,"tool_name":"search_products","status":"SUCCEEDED","latency_ms":45}}

event: recommendation_snapshot
data: {"recommendation":{"rank_no":1,"sku_id":2001,"validation_status":"VERIFIED"}}

event: run_completed
data: {"run_id":"run_001","status":"SUCCEEDED"}
```

For terminal runs, the endpoint emits the current replay immediately and closes. If the run is still `RUNNING`, the Gateway may poll `GetRun` briefly with a bounded interval and emit `heartbeat` events until the run reaches a terminal state or the HTTP request context is canceled.

This endpoint is sufficient for frontend recovery and rendering a consistent timeline. It is not a true low-latency stream of live model/tool events.

## Error Mapping

Gateway errors are stable and do not include raw gRPC messages:

| gRPC code | HTTP status | JSON code | Message |
| --- | --- | --- | --- |
| `InvalidArgument` | 400 | `INVALID_ARGUMENT` | `invalid request` |
| `Unauthenticated` | 401 | `UNAUTHENTICATED` | `authentication required` |
| `NotFound` | 404 | `NOT_FOUND` | `resource not found` |
| `FailedPrecondition` | 409 | `AGENT_RUN_FAILED` | `agent run failed` |
| `DeadlineExceeded`, `Unavailable` | 504 | `DEPENDENCY_TIMEOUT` | `agent service timeout` |
| other | 500 | `INTERNAL` | `internal server error` |

SSE setup errors that occur before headers are written use the same JSON error mapping. After SSE headers are written, later polling errors are emitted as:

```text
event: run_failed
data: {"code":"DEPENDENCY_TIMEOUT","message":"agent service timeout"}
```

and the stream closes.

## Security and Privacy

- All Agent routes are protected by the existing auth middleware.
- Gateway forwards the original bearer token to `agent-service`; ownership checks remain in `agent-service`.
- Gateway forwards only valid W3C trace IDs as `trace_id` metadata.
- Gateway never accepts or forwards client-supplied `user_id`.
- Gateway does not expose raw model input/output, raw Tool payloads, provider bodies, JWTs, API keys, addresses, wallet data, or payment data.
- Error responses are taxonomy-only and must not leak dependency details.

## Validation Strategy

Automated checks:

- `agentclient` tests:
  - forwards bearer metadata,
  - forwards only valid trace IDs,
  - adds a deadline,
  - invokes `StartRun` and `GetRun` correctly.
- `AgentHandler` tests:
  - `POST /api/v1/agent/runs` trims and forwards `message` and `session_no`,
  - rejects empty messages,
  - `GET /api/v1/agent/runs/{run_id}` maps run, steps, and recommendations,
  - empty recommendation JSON fields render as valid `{}` and `[]`,
  - gRPC errors map to stable HTTP codes without raw detail leakage,
  - SSE sets expected headers and emits event/data frames for run, steps, recommendations, and terminal status.

Baseline validation:

```text
gofmt -w apps/gateway
go test ./apps/gateway/... -count=1
go test ./services/agent-service/... -count=1
go test ./... -count=1
go vet ./...
git diff --check
```

## Milestone Boundary

M5.1 is complete when an authenticated HTTP client can create an Agent run, replay that run through Gateway JSON, and consume a Gateway SSE event stream based on persisted run state. Because the model provider remains disabled and `StartRun` is synchronous, M5.1 proves Gateway integration and replay UX readiness, not real live LLM streaming.
