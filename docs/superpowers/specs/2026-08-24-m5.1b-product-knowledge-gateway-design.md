# M5.1b Product Knowledge Gateway Design

## Goal

M5.1b exposes product knowledge search through the Gateway so the product detail page can ask product-specific questions and show sourced snippets or controlled fallback states.

## Current Behavior

M3.2 completed knowledge retrieval inside `knowledge-service`:

- `SearchProductKnowledge(SearchProductKnowledgeRequest) returns SearchProductKnowledgeResponse`.
- Requests include `product_id`, `query`, optional `doc_types`, and `top_k`.
- Responses include ordered `KnowledgeSnippet` items and `fallback_reason`.
- Retrieval filters to current `READY` versions and re-checks MySQL chunk visibility before returning.

Gateway currently exposes only knowledge document upload:

- `POST /api/v1/knowledge/documents`

There is no HTTP route for product detail page question answering yet.

## Scope

M5.1b includes:

- Extend `apps/gateway/internal/knowledgeclient` with `SearchProductKnowledge`.
- Add an authenticated Gateway endpoint:
  - `POST /api/v1/products/{product_id}/knowledge/questions`
- Map HTTP request fields to existing knowledge gRPC DTOs.
- Return sourced snippets and `fallback_reason` without generating an unsourced natural-language answer.
- Add Gateway unit tests for client metadata propagation, request validation, response mapping, and stable error handling.
- Record the M5.1b progress in `docs/TASKS.md` after verification.

M5.1b excludes:

- Frontend product detail page implementation.
- New `knowledge-service` proto or repository changes.
- LLM summarization over snippets.
- Cross-service product existence checks in Gateway.
- Operations document list/retry pages.

## API Contract

### Ask Product Knowledge

`POST /api/v1/products/{product_id}/knowledge/questions`

Request:

```json
{
  "question": "这台电脑支持几个 M.2 硬盘位？",
  "doc_types": ["SPEC", "FAQ"],
  "top_k": 3
}
```

Rules:

- The route is authenticated.
- `product_id` must be a positive integer path value.
- `question` is required after trimming.
- `doc_types` is optional. When omitted, `knowledge-service` applies its normal retrieval policy.
- `top_k` is optional. Gateway caps it to `1..5`; empty or zero defaults to `3`.
- Gateway does not accept or forward `user_id`.

Response with sourced snippets:

```json
{
  "snippets": [
    {
      "chunk_id": 9001,
      "document_no": "doc_1",
      "product_id": 1001,
      "doc_type": "SPEC",
      "version": 2,
      "section": "扩展能力",
      "source_page": 4,
      "content": "支持两个 M.2 2280 插槽。",
      "score": 0.82
    }
  ],
  "fallback_reason": ""
}
```

Response when retrieval has no usable source:

```json
{
  "snippets": [],
  "fallback_reason": "NO_SOURCE"
}
```

The Gateway must not synthesize a final answer from snippets. The UI can render snippets and source metadata directly; answer generation is a later, separately designed capability.

## Error Mapping

Gateway errors are stable and do not expose raw gRPC messages:

| gRPC code | HTTP status | JSON code | Message |
| --- | --- | --- | --- |
| `InvalidArgument` | 400 | `INVALID_ARGUMENT` | `invalid request` |
| `Unauthenticated` | 401 | `UNAUTHENTICATED` | `authentication required` |
| `NotFound` | 404 | `NOT_FOUND` | `resource not found` |
| `DeadlineExceeded`, `Unavailable` | 504 | `DEPENDENCY_TIMEOUT` | `knowledge service timeout` |
| other | 500 | `INTERNAL` | `internal server error` |

No MinIO, Milvus, MySQL, vector store, embedding provider, or raw dependency body may appear in HTTP responses.

## Security and Privacy

- The existing auth middleware protects the route.
- Gateway forwards the original bearer token and valid `trace_id` metadata through `knowledgeclient`.
- Gateway never trusts client-supplied user identity.
- Returned snippets contain product documentation content and source metadata only.
- The endpoint does not reveal uploaded object keys, storage credentials, JWTs, API keys, or internal dependency errors.

No generated protobuf code changes are required.

## Validation Strategy

Automated checks:

- `knowledgeclient` tests:
  - `SearchProductKnowledge` forwards bearer and valid trace metadata,
  - adds a deadline,
  - invokes the generated search full method.
- `KnowledgeHandler` tests:
  - maps `POST /api/v1/products/{product_id}/knowledge/questions` request to gRPC,
  - trims `question`,
  - defaults `top_k` to `3`,
  - caps `top_k` at `5`,
  - rejects invalid `product_id`, empty question, and invalid JSON,
  - maps snippets and fallback reason,
  - maps stable errors without raw detail leakage.

Baseline validation:

```text
gofmt -w apps/gateway
go test ./apps/gateway/... -count=1
go test ./services/knowledge-service/... -count=1
go test ./... -count=1
go vet ./...
git diff --check
```

## Milestone Boundary

M5.1b is complete when an authenticated HTTP client can ask a product-scoped knowledge question through Gateway and receive sourced snippets or a stable fallback reason. It does not prove frontend rendering or generated natural-language answers.
